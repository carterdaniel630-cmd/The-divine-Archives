# Carter's Standing Cycle Rule — Pickup → Rework → Standard → Merge (2026-10-17)

**Carter's rule, in his words:** "It should be picked up, reworked, brought to standard, and then merged."

This rule applies to **ALL items going forward**, not just PR #59. Every item goes through the same cycle, in this order. No skipping steps. No waiting in between — when one item finishes the cycle, immediately pick up the NEXT item and run the same cycle. Keep the cycle moving.

## The Cycle, step by step

**1. PICK IT UP.** Read it. Understand what it is, what it is supposed to do, and where it fits in the Archives. Do not start building until you understand it.

**2. REWORK IT.** Rebuild it even better. Do not just copy it. Muse's drafts, previews, and specs are starting points, never the final product — analyze each one and build it EVEN BETTER, then add it to what is already built. Everything adds to the one live site and the one repo. There is no separate build. The staging branch is a workbench, not a second site.

**3. BRING IT TO STANDARD.** Hold it to Carter's bar AND to Claude's own standards. If it does not meet the bar, fix it first — do not ship it. If it is not good enough, it does not merge. Carter's phone check is the verdict on the finished work.

**4. MERGE IT.** Merge only when ALL of these are true:
- The item is completed AND up to standard (Carter's bar + Claude's own standards).
- It is on the running mergeable list (Item 22: `handoff/replies/MERGEABLE.md`).
- Carter approved THAT specific merge. Approval is per-item, not blanket. One merge approval never approves a different merge.

**Then immediately pick up the NEXT item and run the same cycle.** Pickup → rework → standard → merge → next item. Keep the cycle moving.

## After a merge

After a merge, the next thing up gets run through the same cycle right away. Do not pause the cycle after a merge. Report back in plain words after each merge: what merged, what checks passed, what is live — then keep going on the next item.

## What this rule does NOT do

- It does NOT approve any merge by itself. Every merge still needs Carter's per-item approval.
- It does NOT unblock the 900 Theses room. 900 Theses is still blocked on Gates A–D + the intake ruling.
- It does NOT change the standing limits: staging branch only for handoff work, never main except through an approved merge, nothing goes live without Carter's go-ahead.

**900 Theses is still blocked on Gates A–D + the intake ruling. This rule does not unblock it.**
