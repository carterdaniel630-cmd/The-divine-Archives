Received 2026-10-12. Inspection: `sound.js` is fully procedural Web Audio (synthesized noise layers + oscillator one-offs + generated convolution impulses — zero audio downloads). Room data in `wings/*.json`; 3D areas built in `world.js` from `env` sky/ground/fauna.

## (a) ARCHITECTURE (for vr-architecture.md)
- **Listener in XR:** attach `THREE.AudioListener` as child of the camera. In WebXR the renderer updates the camera transform from the headset each frame, so the listener tracks head pose with zero extra code — pilot must assert `listener.parent === camera` and verify a head-turn pans the ambience. (In three.js r186, `AudioListener` also exposes `setMasterVolume` and the WebAudio `context` directly — reuse that context rather than sound.js's private one.) *[Settled differently on this stack, 2026-11-01, AM-AUD-01: the Archives' flat camera is NOT the presenting XR camera, so camera-parenting cannot be the mechanism here. The settled model (architecture §3.5 as amended): the AudioListener owns the single shared context, and its transform is driven each frame from the architecture's `headProxy`. The verification survives in behavioural form — a head-turn must pan the bed and the emitters, tested in-headset (pilot spec §5.11) — in place of the parentage assertion.]*
- **Two-tier mix:** keep sound.js's per-area "ambience bed" (stereo, head-referenced, built by `recipe(env,kind)` — already data-driven from wings/*.json env) + add per-room **positional emitters**: 1–3 `PositionalAudio` nodes per room anchored to real relic/object positions (fountain gurgle at the fountain mesh, ember crackle at braziers, hum at the abyss). Emitters registered in a room-group so they dispose with the room.
- **HRTF panning:** three.js `PositionalAudio` uses a `PannerNode` — spec `panningModel='HRTF'` only for the ≤3 nearest emitters (Quest-class CPU), `distanceModel='exponential'`, per-relic `refDistance`; remaining emitters use `'equalpower'` (cheap). Stereo-panned one-offs (crickets, birds) stay non-spatial bed calls.
- **Reverb zones:** extend sound.js's single convolver (its `impulse()` already *generates* IR — keep it, no external IR files ever): 3 generated presets — rotunda/large hall (4s decay), stone room (2.6s, existing), open sky (0.9s, mostly dry). Wing JSON gains `verb:` key; `verbIn.gain` ramps on room change.
- **Wing-transition crossfades:** keep sound.js's `stopBed`/`startBed` 3.5s fade; add a wing-key check so adjacent rooms in the same wing swap only emitters and reverb, never tearing down the shared bed.
- **sound.js migration checklist:** KEEP `buffers()/LAYER/CALL/recipe()/impulse()/createSound` as-is (they're zero-weight and already solemn). MERGE: single shared AudioContext via the AudioListener; emitter registry with `dispose()` per the Modular Framework Standard's destructor clause. ADD: XR listener binding, per-wing reverb presets, mute buses (below), caption bus. DO NOT: add any sampled assets or CDN audio.
- **Autoplay/XR gesture:** `requestSession` on Quest must originate from a user gesture, so bind `ctx.resume()` to both the "Enter VR" click and the `sessionstart` handler — do NOT assume session entry alone unlocks audio; spec both paths. Also handle `visibilitychange` suspend/resume.

## (b) BUDGETS (for vr-performance-budget.md)
- Audio CPU on Quest-class silicon: **≤5% of frame budget**. Hard caps per room: ≤6 concurrent positional emitters (≤3 HRTF at a time — nearest-to-head priority), ≤8 continuous procedural layers total, ≤40 live audio nodes.
- **Procedural-vs-sampled verdict: 100% procedural, zero sampled assets.** sound.js already proves it; sampled files would violate zero-CDN and add fetch weight. If Claude Code ever adds a sampled loop: mono 44.1kHz, ≤200KB/loop, total audio ≤2MB — currently budget is **0 bytes**.
- Voice/CPU guard: tick-driven one-offs (thunder, bird calls) keep their rate-limited `RATE` table; in XR drop high-rate one-offs >15m from head (they're inaudible anyway).

## (c) ARTISTRY (for vr-artistry-addendum.md)
- **Soundscape design language:** every wing's sound is drawn from its real content, never fantasy-drone. *Bronze Age (Egypt):* desert wind bed, slow Nile water, **distant bronze-hammer strikes** (bandpassed noise blips, metallic decay) near metalwork relics; the Amarna room is near-silent — only breath of wind. *Prehistory:* cave drips, ember crackle, **flint-knap clicks** (diegetic!) when near tool relics, owl in night rooms. *High Medieval (cathedrals):* 4s reverb, stone drips, and a whisper-quiet low organum interval (55/82.6/110Hz triangles, −30dB) — one sustained interval, never a melody.
- **Silence as sacred:** NO ambience in the rotunda on first arrival; ~~rooms marked `pending:true` play silence (nothing written = nothing said)~~ *[rule struck 2026-11-01, AM-AUD-02: under Carter's pending-review ruling a pending room stands live BY DESIGN, and a blanket silence keyed to `pending: true` made the pilot's lead room contradict its own designed bed while teaching visitors that new rooms are lesser. **Settled rule: embodied rooms carry their designed beds** (pilot spec §3 soundscape map); silence in this program is a room-specific artistry choice — the burial chamber's hush — and carries no status meaning. The general question for non-embodied rooms remains Carter's (alignment doc OQ-4).]*; when a relic is being inspected, the bed ducks 60% so the object "speaks first"; sacred-designated rooms cap at 2 concurrent layers. Transitions use 2–3s eases (séance pacing — `setTargetAtTime` with τ≥1.0 on every bed change).
- **Diegetic feedback vocabulary (never sci-fi beeps):** UI open = stone click (filtered click transient); wing change = soft bronze chime (880→660Hz triangle, 1.2s decay); inspect panel = parchment whisper (highpassed noise burst 0.15s); locomotion step = pebble crunch (brown-noise burst, −24dB). No hover sounds, no square-wave pings, ever.
