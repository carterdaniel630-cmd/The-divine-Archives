## What was built — `loop/vr-perf-overlay` `ee7ffc76`, PR #189
- `docs/assets/vr-perf-overlay.js` (the §7 module, beside `fps-overlay.js`). It does nothing unless the address is
  `museum.html?vrfps=1`. `app.js` imports it only then, so no visitor downloads it.
  - **In the headset** it shows a plate low in the view. It is fixed to the head because it is a measuring
    instrument, and it only appears with the flag. It is drawn last with no depth test, so walls never hide it.
  - **On a flat screen** the same lines show in a bottom-left box.
  - **Frame time:** measured from the gaps between the XR session's own frame timestamps (the compositor's clock).
    It shows p95 and worst for the last second, and for the whole run and each area. The run and area figures come
    from a 0.25 ms histogram that reads the upper edge of each bin, so they are never optimistic.
  - **Hitches over 20 ms:** counted in three groups: normal hitches; hitches in the first 2 s (warm-up); and hitches
    on the frame right after the overlay's own once-a-second scan. The scan takes about 0.7 ms in software. Keeping
    that group apart means the overlay's own cost never shows up as the museum's.
  - **Counts:** stereo draw calls and triangles from `renderer.info` after the frame, which covers both eyes. The
    plate itself costs 2 calls (1 per eye); this is reported as `overlayCalls` and included in the raw count.
  - **Once a second:** lights switched on, shader programs (and any growth after warm-up), textures, and the in-view
    texture ledger. Like the harness, the ledger is an upper bound, so it is **shown, not judged**.
  - **Verdict:** compared against the Quest 2 ceilings (Quest 3 on a Quest 3): p95 ≤ 13.9 ms, calls ≤ 160, triangles
    ≤ 350k, lights ≤ 5, no hitch. An area's p95 is judged only after 300 frames; before that it reads MEASURING.
  - **Areas and runs:** figures are kept for each area (the "where" label). Leaving VR and coming back starts a new
    run.
  - **For tools:** the same figures are on `window.__vrfps`, and `window.__vrfpsReset()` starts a new run.
- `docs/museum/app.js`:
  - the conditional import;
  - `S.perf.frame(now)` after both `renderer.render` calls in `tick()`;
  - test hooks `__MU.vrfps()` and `__MU.vrfpsImage()`.
- `museum.html`: `app.js?v=60`.
- `tools/vr-perf-overlay-check.js`: the stand-in check (below).
