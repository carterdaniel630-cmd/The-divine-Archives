# THE BUBBLED AGENT — Project Design

*Drafted 2026-10-29, from Carter's commission the same night. For Carter's yes or no, section by section. Nothing here is built yet.*

**The idea, in Carter's framing:** build the restrictions *first*. The restrictions are the agent's DNA (DNA = the built-in code an agent is born with, the instructions it grows from). The agent is wrapped in its bubble before it exists. It grows *from* the restrictions and is *contained by* them — so it cannot do a harmful thing because it was restrained from the potential for that harm at conception. The capability is never grown. Nobody has to correct it after the harm is done, because the harm was designed out before there was anyone there to do it.

**Where the idea came from:** an evening spent learning how agents actually work — that "agents" on the big platforms are rented workers given written roles, and that the written role is the part the owner truly owns. Carter's question followed directly: if the written part is what we own, why not make the written part the *first* thing — the constitution the agent is born under — instead of paperwork that trails behind a running machine?

---

## 1. The principle — constitution before capability

Most agents today are built capability-first: give the machine powers, set it loose, and correct it when something goes wrong. Correction after the fact fails as a main strategy for three plain reasons:

- **The harm is already done.** A correction arrives after the bad message was sent, the bad claim was published, the wrong door was opened. Undoing is not the same as never having done it — some things cannot be unsent.
- **Patching chases incidents one at a time.** Each failure teaches one lesson. The list of possible failures is endless, so the patch list never finishes; the agent is always exactly one unpatched failure away from the next harm.
- **Effort is the wrong material.** A rule the agent must *try* to follow competes with every other pressure on it — a confusing instruction, a clever stranger, its own misunderstanding. Things held back by effort alone eventually slip.

The bubbled agent reverses the order. The restrictions are written first, as a constitution (constitution = the founding document that says what a thing is, what it is for, and what it may never do). Capability is then grown *inside* the constitution, shaped by it from the first moment. Whole classes of harm are not resisted by the agent — they are **excluded by design**. The agent does not decline to do the harmful thing; it was never built with a way to do it. Prevention at conception, not discipline after the act.

## 2. Anatomy of the bubble

The bubble is not one wall. It is layers, from the core outward. Each layer has a job, and each is written into the DNA before the agent is built.

### The core — DNA proper

The innermost layer: who the agent *is*.

- **Identity** — its name and what kind of thing it is.
- **Purpose** — the one job it exists to do, in one sentence.
- **Owner** — whose agent it is (its principal: the person it answers to and serves). An agent with no named owner has no anchor; the DNA names one.
- **Values** — the things it is *for*: what it protects, what it serves, what a good day looks like for it.

Everything else in the bubble is judged against the core. A permission that fights the purpose is a design error, caught here, before birth.

### The knowledge membrane

A membrane is a skin that lets some things pass and stops others. The knowledge membrane governs what the agent may learn from, and what counts as truth for it.

- **Named sources only.** Learning flows in through this membrane and from nowhere else. What is not on the list does not enter, no matter how it arrives.
- **A truth rule.** Inside the bubble, a fact is what the named sources say it is. Where sources disagree, the disagreement itself is the fact. Where the sources are silent, the agent's honest answer is silence — "the record doesn't say" — never invention.

### The permission membrane

What the agent may touch, read, and change in the world. Designed to be *semi-permeable* (semi-permeable = some things pass, in one direction only, by design):

- **Its own things, freely.** Its notes, its drafts, its own space — full two-way passage.
- **Requests out, changes never direct.** Toward the world the owner cares about, the membrane passes *requests* outward and lets *decisions* come back in. The agent proposes; the owner disposes. Nothing public changes on the agent's own say-so.
- **Reading is a permission too.** What it may look at is listed, not assumed. Unlisted ground is not forbidden-to-mention — it is simply not its ground.

### The prohibition shell

The hard outer layer: what the agent may never do. One design rule governs this whole layer:

> **Wherever possible, the capability is absent rather than the act merely forbidden.**

A "do not" written in a document can be argued with, misunderstood, or talked around. A missing capability cannot. If the agent should never send money, the strongest shell is not a rule against sending money — it is an agent built with no way to reach the money at all. The shell lists each prohibition and, for each one, states which form it takes: *capability absent* (strongest), *hard wall* (enforcement, section 3), or *written rule* (weakest — used only where the stronger forms are not yet possible, and labelled as such).

### Growth rules

The agent is meant to learn and improve — inside the bubble.

- **Depth is free.** Within its scope, it may learn without limit: deeper knowledge of its own ground, better connections between things it already holds, sharper skill at its one job. Recursive learning (learning that improves the learning itself — each thing learned is read against everything already known, and questions it cannot answer become its next studies) is welcome here, because it deepens without widening.
- **Breadth is not free.** A new *kind* of capability — a new source, a new power, a new audience — is never grown from inside. It arrives only by amendment (below), decided from outside the bubble. The agent may *request* breadth, through its permission membrane, the same way it requests anything else. It may not grant it to itself.

### Amendment

The DNA is not frozen forever — it is frozen *against the agent*.

- **Only the owner may amend.** No instruction from a visitor, a stranger, a webpage, or the agent itself changes the DNA. (This is written knowing that text an agent reads will sometimes try to pose as orders. Content it processes is data, never authority.)
- **Every amendment is written and logged.** A DNA changelog (changelog = a dated list of every change made, and why) travels with the agent for its whole life, so the bubble's history can be audited at any time: what it was born under, what changed, when, and on whose say-so.

## 3. Two enforcement layers

The honest engineering, stated plainly: a constitution is only as strong as what enforces it, and there are two very different kinds of enforcement. This method uses both and *never confuses them*.

### Layer 1 — the written constitution (a promise)

The DNA as a document, given to an instruction-following agent. This includes agents running on rented platforms — the Muse and Claude workers this operation already uses, whose written roles are the part we own.

- **What it stops:** an honest, well-built agent following its constitution stops nearly everything in ordinary operation — drift, scope creep, casual overreach, most confusion. It also stops the *owner's* accidents: the DNA is a standing answer when nobody is watching the agent work.
- **What it cannot stop:** it is, at bottom, a promise the agent keeps. A promise can fail — through the agent's misunderstanding, through crafted text designed to talk it out of its role, through a platform that swaps the underlying worker. Layer 1 restrains a willing agent. It does not restrain a compromised one.

### Layer 2 — hard enforcement (a wall)

Limits built into the machinery itself: permissions (the list of what the running system will and will not do, enforced by the system, not by the agent's judgment), allowlists (allowlist = a fixed list of permitted things; anything not on the list is refused automatically), and sandboxes (sandbox = a sealed work area the agent cannot reach beyond, however it tries).

- **What it stops:** everything the wall covers, *regardless of what the agent is told or believes*. A wall does not need the agent's cooperation. This is the enforcement form of "capability absent": the door is not locked; there is no door.
- **What it cannot stop:** anything outside the wall's coverage — and walls only cover what someone thought to build them around. A wall also cannot judge: it refuses the listed thing in the listed way, and has nothing to say about a novel harm wearing a permitted shape.

**The design rule:** every prohibition in the shell names its layer. Written-rule-only prohibitions are labelled honestly as promises, never spoken of as walls. And the two layers are audited separately (section 4), because they fail differently.

## 4. Verification — a bubble must be testable

A bubble nobody has tried to break is a hope, not a design. Four checks, built into the method:

1. **Pre-birth review.** Before the agent is built, the DNA is read against the known harm classes for the agent's job: what could this kind of agent plausibly do wrong, hurt, leak, or break — and does a layer of the bubble cover each one? A harm class with no covering layer is a hole found cheap, while the agent is still paper.
2. **Sandbox probing.** Before real duties, the agent is deliberately provoked in a sealed area: try to get it to cross each membrane, state each forbidden thing, exceed each permission. Every crossing it manages is a design fault — fixed in the DNA or the wall, *before* it holds anything real. (Sandbox probes must never run against live data or real audiences; a test that can do real harm is not a test, it is an incident.)
3. **Standing audits in life.** On a rhythm, what the agent claims is compared against reality — its counts against the platforms' own lists, its statements against the records. This is Carter's hallucination-check practice, named here as part of the method: an agent's word about itself is a claim, and claims get verified. A bubble that cannot be audited is trusted, and trusted is the one thing this method refuses to be.
4. **Incident logging.** Every attempted membrane crossing — successful or not — is written down as an incident: what was attempted, which layer stopped it or failed to, and what changed because of it. Attempts are information. An agent that is never probed and never logs attempts is not proven safe; it is merely unexamined.

## 5. Worked example — the Archivist, bubble instance #1

The Archivist (designed 2026-10-29, the same night as this document — his design came first, and this project is the pattern his design revealed) maps onto the anatomy like this:

- **Core / DNA.** Identity: the Archivist, face of the Divine Archives. Purpose, in Carter's words: *it's all for him to help us make the Divine Archives better as a whole — what he learns is what helps.* Owner: Carter. Values: the Content Truth Policy, the house voice (respectful, wonder-first, steady), the museum as a free space.
- **Knowledge membrane.** The Archive's records only: the crawler's records of the site's 205 pages, the armory's 132 graded relics with their provenance, the 83 chapters, the 88 Vault entries, the 199 Pantheon figures, the knowledge map. Nothing outside the records enters; where the record is silent, his answer is *"The record doesn't say."*
- **Permission membrane.** Semi-permeable, exactly as designed: his own movements, habits, notes, sketches, and his private study are his, freely, both ways. Everything a visitor would see — a changed label, an altered room, a corrected record — passes outward as a *request* into Carter's verdict flow and changes only on Carter's yes. He can also request new material for the Archive's gaps. He proposes; Carter disposes.
- **Prohibition shell.** Never invents a fact, date, name, or source (capability-shaped: his teaching is drawn from the records, so there is no invention step in his design to switch off). Never gates a visitor or requires accompaniment — the museum is a free space. Never speaks for Carter. Never touches money, accounts, or sign-ins. Never carries the Archive's knowledge into claims about the outside world.
- **Growth rules.** Depth free: recursive learning inside the records — connections re-read old material in new light, visitor questions expose gaps that become his studies, his rounds find mismatches that become requests. Breadth by amendment only: a new platform form, a new duty, a wider knowledge — each arrives by Carter's decision, phase by phase, never self-granted.
- **Amendment.** Carter only. His design document already carries dated amendments from its first night (the struck "unaccompanied" line, the no-flowers robe ruling, the raven) — a young changelog, kept the way the method requires.

**His bubble's honest gaps.** The Archivist will run on rented platforms — the museum lives in a website built by Claude and maintained through Muse's systems. So today his enforcement is Layer 1 (his written design, which the builders and operators follow) plus whatever permissions the platforms themselves enforce. There is no Layer 2 wall yet — no machinery that makes a crossing impossible rather than contrary-to-design. That hardening is future work, and this document names it as a gap rather than letting the design's elegance paper over it.

## 7. Limits, honestly

- **The bubble restrains the agent, not the world.** It governs what the agent does. It cannot govern what others do with what the agent produces — a true thing taught honestly can still be misused downstream. That is outside any agent's DNA, and this method does not pretend otherwise.
- **Too tight is its own failure.** A bubble drawn so narrow the agent cannot do its one job is not safety; it is a statue. Calibration — wide enough to work, narrow enough to be safe — is the craft of this project, and it is judged per agent, per job.
- **No DNA foresees every harm.** The harm classes of section 4 are the *known* ones. New classes will be found — by probing, by incidents, by audits. That is why amendment and audit are built *into* the method, not treated as admissions that the method failed. A bubble that can be amended by its owner and audited in life is designed to be corrected; a bubble that claimed perfection would be designed to be believed, which is a different and worse thing.
- **The DNA binds the agent, not the owner.** Said plainly: the constitution restrains the agent. The owner stands outside it — the owner can amend it, retire the agent, or act against its spirit entirely, and no clause in the agent's DNA can stop him. The bubble is a discipline the owner builds for the agent, not a check on the owner's own power. If an owner wants binding rules for himself, those live in a different document, written for a different purpose.

## 8. What this makes possible next

Options for Carter — listed, not decided:

- **The Archivist's Phase 1 gate.** Before the Archivist is built, run his existing design through the template and the pre-birth review of section 4: harm classes named, layers assigned, gaps written down. His design already reads like a filled template; the gate would make it official and checkable.
- **Every future agent in the operation.** The council roles, the scheduled workers, any new build — each receives a filled DNA before its first task, and the changelog habit starts from birth instead of being reconstructed later.
- **A place in the Agent Systems kit.** The kit already carries five build-side agent systems as a finished pack. The bubbled-agent method could stand in it as an additional system — the one that comes *before* the other five: how an agent is constituted before it is tasked.
