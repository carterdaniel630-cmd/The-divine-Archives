      hand run started from a feature branch would publish that branch's map
      labelled "main @ <sha>" (lines 109, 116).

    the publishing steps; run them only for main (not pull requests or other
    branches); correct the comment.
    Safe already: the two force-pushes are fixed to graph:graph and
    graph-tools:graph-tools from a fresh temporary repo (lines 113-119,

    Actions are pinned to major versions (@v4/@v5) like every other workflow

  - site:graphify-vendor: the graphify licence notice is missing.
    * The vendored skill (.claude/skills/graphify/, 9 files) is byte-for-byte

    * graphify is Apache-2.0, with some older parts under MIT (its package
      ships LICENSE, LICENSE-MIT and NOTICE). This repository is public and

      it came from. Apache-2.0 section 4 asks for both when the work is
      passed on.
    Fix: copy LICENSE, LICENSE-MIT and NOTICE from the 0.9.85 package into
    .claude/skills/graphify/, plus one line naming the source (graphify
    0.9.85, github.com/Graphify-Labs/graphify).

      exception, and LGPL), which numpy's own licence file covers.
      tree-sitter-groovy 0.1.2 says MIT but ships no licence file. The branch
      README lists none of this.
    Fix: have the workflow write a licence list into the graph-tools README.
    * Only graphify's own version is pinned. The packages it needs are picked
      fresh at each build (graph-tools holds two numpy and two networkx
